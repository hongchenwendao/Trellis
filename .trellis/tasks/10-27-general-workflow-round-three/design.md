# Design: trust complete content, recover only gaps

The initial gap is in instructions: shared/Pi hooks already emit `[Trellis: truncated ...]` and `[Trellis: not inlined ...]` notices, while the class-1 agent profile treats the hook marker as proof of completion and later commands reread whole artifacts. Codex native profiles understand host-saved output but also trust the marker too broadly. The shared pull prelude additionally tells Pi to reread despite its extension's `Trellis Task Context`. Preserve limits, artifact order, task-path containment, and no-hook fallback; do not invent a completeness flag or state database. Review later found missing/rejected references were silently omitted, requiring the narrow payload/path correction below.

A new child first identifies its own active task. If full, relevant task/spec blocks are present in its current prompt, it uses them directly. It follows a `Full hook output saved to` host notice before judging visible completeness, then reads only named truncated/index-only/missing files and any relevant spec not supplied. If injection is absent, it loads the role's JSONL, task artifacts, and relevant specs from disk. After compaction/new session or a task/source change, refresh affected information; the parent's earlier reads do not transfer. A marker alone is not a completeness claim.

The per-turn execution blocks will become concise gate-and-route reminders. Phase 2.1/2.2 and 3.3/3.4 detail, skill checklists, and agent profiles remain the retrievable instructions. The old breadcrumb contract's effect is preserved by naming the required implement/check/spec-update and conditional commit/finish gates in the compact block, plus an explicit `get_context.py --mode phase --step` route. Tests will check gate presence and actual step extraction rather than exact old prose.

Review of the candidate exposed two concrete gaps. A Pi child receives a task block even when its role manifest is empty, so the pull prelude must treat task artifacts without curated specs as a separate recovery branch. A mixed valid/missing JSONL manifest previously hid the missing path in both Python and Pi. Keep valid blocks, add a named unavailable notice, and distinguish rejected outside-root references from missing files. The Pi read entrance is confined to the real repo or real `.trellis` root, including a legitimate externally symlinked `.trellis`; symlink/`..` escapes remain unreadable. The detail command in each short breadcrumb must pass the actual `--platform` so Codex inline never receives dispatch instructions.

Final review found the same gap for the existing legal `type: "directory"` manifest entry. Python now retains directory path/reason when a directory is missing, unreadable, empty, partly materialized, or disallowed; it refuses to enumerate an outside-root directory. Pi does not recursively expand directory entries; it keeps the path/reason and distinguishes an allowed directory (inspect relevant Markdown files) from missing and disallowed ones. This changes notices and containment only, not the JSONL schema, budget caps, or recursion policy.

Change candidates: native workflow and current copy; class-1 implement/check profiles, Codex native-hook profiles, shared pull prelude for Pi, relevant shared hook prompt wording and `before-dev`/`continue` entry guidance; related spec/tests and generated copies. Only edit a hook or extension if its actual payload lacks a path to this decision. No parser or budget change is planned.
