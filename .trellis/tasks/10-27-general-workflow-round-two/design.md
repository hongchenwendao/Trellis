# Design: execution owner plus risk-triggered review

The gap lives in workflow guidance and agent prompts, not in task-state parsing: the current in-progress breadcrumb and Phase 2 detail prescribe `trellis-implement` → `trellis-check` for every task, while reviewers are told to self-fix any size of finding. The Codex `auto` banner repeats the fixed relay. Planning also requires both role manifests merely because the host supports sub-agents. Keep phase names, context loading, dispatch prompt contract, and config normalization unchanged.

For each authorized development slice, choose one execution owner. The main session can own a simple bounded slice or dispatch an implementer for an independently deliverable result. The owner investigates, writes, runs relevant tests/checks, repairs, and provides evidence. Select an independent reviewer for a changed public interface, substantial cross-module change, important risk, or user/project mandate; this is based on actual consequences, not file count. It checks omissions, design drift, and integration risk. If no independent agent is available or `inline` prohibits dispatch, use the local check path and report that independence was unavailable. A reviewer fixes small assigned issues, but returns substantial rework to the execution owner. Final integrated acceptance remains with the main session.

Prepare `implement.jsonl` before dispatching an implementer and `check.jsonl` before dispatching a reviewer. The existing `task.py start` default still rejects an empty seeded manifest. For the selected direct route—or when only one role's manifest is ready—use its existing `--allow-empty-context` option; this bypasses only the start-time gate, not the requirement to curate a role before dispatch. Inline/direct owners read relevant specs via `trellis-before-dev`; delegated roles retain existing injection and child-side fallback. No config/parser mode or task schema changes.

A check is evidence for a specific candidate and inputs/premises. Keep it if those are unchanged; after a code/input/premise change rerun only impacted checks, plus final full-scope acceptance and mandated hooks/CI at their required point. This is a guidance rule, not a cache/hash implementation.

Expected changes: bundled/native workflow and local copy; common check and continuation guidance; per-platform implement/check prompts, channel built-ins, Codex banner/config explanation and directly relevant spec/README; targeted tests and current-project generated copies. Do not alter config parsing, task lifecycle, marketplace, or channel runtime.
